详细专题

专题一：grep 详解

grep = 按行匹配模式并输出。核心是”模式 + 选项 + 目标“。

1. 基本语法

  • 不给文件：从标准输入读（常配合管道）
  • 给多个文件：输出会带文件名前缀
  • 给目录：需加 -r

2. 匹配模式（正则）

基础正则（BRE）

符号 含义
. 任意单个字符
* 前一个字符 0 次或多次
^ 行首
$ 行尾
[] 字符集合，如 [abc]、[0-9]
[^] 排除集合
\ 转义

扩展正则（ERE，用 -E）

符号 含义
+ 1 次或多次
? 0 次或 1 次
{n} {n,m} 精确次数
| 或
() 分组

区别：基础正则里 + ? { } | ( ) 要加 \ 转义，-E 不用。-F 则完全不解析正则，按字面串匹配。

3. 选项全表

输出控制

选项 说明
-n 显示行号
-H 总是显示文件名
-h 不显示文件名
-o 只输出匹配的部分
-c 只输出匹配行数
-l 只输出含匹配的文件名
-L 只输出不含匹配的文件名
-q 静默，用退出码判断
--color=auto 高亮匹配

匹配控制

选项 说明
-i 忽略大小写
-v 反向匹配（不含的行）
-w 匹配整词
-x 匹配整行
-F 固定字符串，不当正则
-E 扩展正则
-P Perl 正则（支持 \d \w 等）

上下文

选项 说明
-A n 匹配行后 n 行（after）
-B n 匹配行前 n 行（before）
-C n 前后各 n 行

文件与目录

选项 说明
-r 递归目录
-R 递归并跟随符号链接
--include=*.c 只搜匹配文件
--exclude=*.log 排除文件
--exclude-dir=.git 排除目录

4. 实战示例

5. 退出码

码 含义
0 匹配到
1 没匹配
2 出错（文件不存在等）

脚本里常用 -q + &&/|| 做条件判断。

6. 常见坑

  • 模式含空格/特殊字符要加引号，否则 shell 先展开
  • 搜固定字符串用 -F，避免 . * 被当正则
  • ps aux | grep xxx 会匹配到 grep 自身，用 grep [x]xx 或 grep -v grep
  • 二进制文件提示 binary file matches，用 -a 强制当文本
  • 递归大目录加 --include/--exclude 提速
  • -P 不是所有 grep 都支持（GNU grep 有）

7. 相关命令

命令 说明
egrep = grep -E
fgrep = grep -F
rg（ripgrep） 更快，默认递归、忽略 .gitignore，大项目首选
ag 类似 rg

专题二：管道详解

管道 | 把前一个命令的 stdout 接到后一个命令的 stdin。

1. 基本语法

数据流：cmd1 输出 → cmd2 处理 → cmd3 处理 → 屏幕。

2. 三个标准流

流 描述符 管道默认
stdin 0 接收
stdout 1 传递
stderr 2 不进管道

关键点：stderr 默认仍打到屏幕，要让它进管道：

3. 管道的阻塞与 SIGPIPE

  • 前命令写满管道缓冲区会阻塞，等后命令读
  • 后命令提前退出（如 head），前命令收到 SIGPIPE 被终止

4. 与其他重定向配合

写法 含义
cmd > file 输出覆盖到文件
cmd >> file 追加
cmd 2> err.log 错误到文件
cmd > out.log 2>&1 输出和错误都到文件
cmd > out.log 2> err.log 分开
cmd < input.txt 从文件读输入
`cmd tee file`
`cmd tee -a file`

专题三：export 详解

export 的作用：把 shell 变量 变成 环境变量，让子进程能继承。

1. shell 变量 vs 环境变量

类型 作用范围 创建方式
shell 变量 仅当前 shell VAR=value
环境变量 当前 shell + 所有子进程 export VAR=value

本质：环境变量是每个进程都带的一份”键值表”，fork 时复制给子进程；shell 变量只在 shell 内部。

  • export 在子 shell 或脚本里执行，退出后失效，不影响父 shell
  • 配置文件里写 export，source 才生效，直接 ./file 只在子 shell 生效

专题四：环境变量详解

1. 概念

环境变量是操作系统/程序运行时的配置，每个进程都有一份，fork 时继承、exec 时传递。

2. 生命周期与作用域

  • 只向下传，不向上传：子进程改环境变量，父进程不知道
  • 只影响之后启动的进程：已经在运行的程序不会变

3. 加载顺序（登录时）

非交互式（如脚本）通常只读 $BASH_ENV，不读 .bashrc。

4. 各配置文件对比

文件 生效范围 生效时机 适用
/etc/environment 所有用户 登录 系统级，纯 KEY=value，不支持 $PATH 展开
/etc/profile 所有用户 登录 系统级登录 shell
/etc/profile.d/*.sh 所有用户 登录 推荐放系统级变量
/etc/bash.bashrc 所有用户 交互式 bash 系统级 bash
~/.bash_profile 当前用户 登录 用户级登录 shell
~/.bashrc 当前用户 交互式 bash 用户级最常用
~/.profile 当前用户 登录 通用（非 bash 也用）

专题五：软链接详解

软链接是指向另一个文件的特殊文件，类似 Windows 快捷方式。

1. 创建

注意参数顺序：ln -s 目标 链接，目标在前。

2. 硬链接 vs 软链接

特性 硬链接 软链接
命令 ln 目标 链接 ln -s 目标 链接
inode 与目标相同 独立 inode
跨文件系统 ❌ ✅
指向目录 ❌（一般） ✅
目标删除后 仍可用（数据还在） 失效（悬空链接）
大小 同目标 路径字符串长度
ls -l 显示 普通文件 l 开头 + ->

6. 相对 vs 绝对路径

相对路径的坑：相对的是链接所在目录，不是当前目录。移动链接后可能失效。

8. 特殊注意

  • ln -s 目标不存在也能创建（生成悬空链接），不会报错
  • cp 软链接：默认复制指向的内容，cp -d/-a 保留链接本身
  • tar 打包：默认存链接本身，-h 则跟随
  • rsync -l 保留链接，-L 跟随
  • 循环链接：a -> b，b -> a，遍历时会报 too many levels of symbolic links
  • 权限：软链接权限无意义（多为 777），实际看目标权限
